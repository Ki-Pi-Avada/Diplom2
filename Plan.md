# План тестирования и автоматизации

## Цель и границы

В этом плане описано тестирование приложения «Мобильный хоспис» на Android и автоматизация пользовательских сценариев. В объём работы включены авторизация и выход, главный экран и навигация, список и фильтры новостей, панель управления, операции с новостями и тематические цитаты на экране «Наша Миссия».

Backend проверяется только через пользовательские сценарии приложения. Нагрузочное тестирование и отдельные проверки API в дипломный проект не включены.

## Виды тестирования

В работе применялись функциональные и UI-проверки, позитивные и негативные сценарии, smoke-проверка запуска и навигации, а также регрессионные проверки основных функций. Дополнительно проверялись базовая прокрутка и переходы между экранами на отсутствие аварийного завершения.

## Окружение и инструменты

- Android Studio, JDK 17 и Android SDK Platform 36;
- эмулятор или устройство с Android API 36;
- тестовый backend и учётная запись `login2` / `password2`;
- Java 17, JUnit 4, Espresso, UiAutomator и Page Object Model;
- Allure Kotlin Android для описаний, шагов и скриншотов при падении;
- Git для истории изменений.

Для управления новостями требуется учётная запись с правами администратора. Для запуска тестов необходимы подключение к сети и доступность backend.

Текст Toast при ошибке авторизации и валидации не сверяется, поскольку он нестабилен. Вместо этого проверяется, что вход не выполнен, а форма остаётся открытой. Фильтры по датам, отмена удаления и редактирования, длинная прокрутка и часть нефункциональных проверок оставлены для ручного тестирования.

## Порядок работы

1. Проверить сборку и окружение Android API 36.
2. Выполнить ручные проверки по `Check.xlsx` и отметить только фактический результат.
3. Сверить кейсы в `Cases.xlsx` с Java UI-набором.
4. Запустить UI-тесты и сохранить Allure-результаты.
5. Зафиксировать дефекты и сравнить время ручной проверки с автопрогоном в `Result.md`.

## Критерии готовности

Комплект считается готовым, когда сборка и тесты запускаются на API 36, покрытие и ручные результаты отмечены раздельно, в корне находится архив чистого полного прогона Allure со всеми 34 методами, а в `Result.md` указаны результаты и время проверок.
